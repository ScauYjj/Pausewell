# Windows 技术验证与交互原型 Implementation Plan

**Goal:** 将已认可的方案落实为明确规则、可运行的 Windows 原型和有证据的技术验证。

**Architecture:** 本地业务核心独立于 WPF 窗口，通过单次事项状态驱动提醒。SQLite 原子保存状态；桌面适配处理托盘、多屏和会话事件。默认不启用后台提醒，用户主动开始后运行。

**Tech Stack:** .NET 10、C#、WPF、Windows 自带 SQLite、无云端依赖。

## 执行步骤

1. 检查 Windows 开发环境。缺少 SDK 时将官方 SDK 安装到项目 `.tools/dotnet`，不修改全局 PATH。
2. 写入 `docs/specs/reminder-rules-v0.1.md`，固定循环语义、药物状态、会议策略和恢复规则。
3. 创建 `src/Pausewell.Core`，实现计划、事项、状态和可注入时间的调度服务。
4. 创建 `tests/Pausewell.Specs`，先覆盖延期、固定时间、会议、恢复、重复操作和失败保存。
5. 创建 `src/Pausewell.Storage`，使用 Windows SQLite 保存版本化状态与审计记录；验证重开数据库。
6. 创建 `src/Pausewell.Desktop`，实现今日、计划编辑、历史、验证设置及提醒窗口。
7. 增加托盘、单实例、锁屏与睡眠恢复、多屏覆盖与紧急退出。
8. 构建，执行规则验证与独立测试数据下的 GUI 冒烟测试，截取实际渲染图。
9. 输出可启动目录、启动脚本、用户说明和验证报告；标明实际睡眠、共享和更多设备的待验项目。

## 验收用例

- 09:37 完成 30 分钟间隔事项，下一次 10:07。
- 延期不改变事项身份，也不写入完成。
- 固定服药时刻不随确认时间平移；不同药物独立记录。
- 会议只改变呈现，到期自动恢复，普通待办合并展示。
- 重启不重复完成事项；恢复时错过的服药事项进入待核实。
- 保存异常不提交内存完成状态，不暗示重新服药。
- 强提醒普通关闭受限，紧急退出可用且不写入完成。
- 测试提醒不修改真实计划与实际服药记录。

## 本阶段边界

提供实际 Windows 交互原型，不含云同步、自动会议识别、自动更新和正式签名安装包。不锁屏、不改变系统时间、不强制睡眠、不修改开机启动。真实药物示例默认关闭。
