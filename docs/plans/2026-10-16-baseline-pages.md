# 三个基准页面 Implementation Plan

**Goal:** 在已确认组件和现有材质基础上交付首页、普通提醒编辑、药物编辑的独立原生页面样板，验证完整交互与核心规则绑定。

**Architecture:** 新建 `design/page-lab`，复用 `Pausewell.Controls` 和材质源码，引用真实 `Pausewell.Core`、使用仅内存 IStateStore 和固定演示时间。没有后台计时器、SQLite 或系统设置操作。已发布程序与数据保持原状。

**Tech Stack:** .NET 10 WPF、既有材质资源、原生 UI Automation、真实业务引擎、原生截图。

## 页面设计

首页复用四入口导航，实际接入提醒和药物两个基准列表；记录和设置清楚标示后续接入。标题、状态、会议/暂停、下一次卡片、分组列表及空态共用布局。新建和编辑使用一致的表单窗口，标题与底部操作固定、主体滚动。

普通编辑以名称、事项、循环间隔、提醒方式为主体；高级设置容纳固定时刻、工作日和有效时段；活动时长按事项显示。药物编辑使用互斥次数和明确时刻、日期组、提醒方式、既有用药说明。变化即时更新预览，字段级错误保留输入。

减少次数暂时隐藏多余时刻，增加时恢复会话草稿，不自动推算服药间隔。保存仅提交当前次数，重复、无效时刻和日期范围阻止提交。取消不改引擎状态；有修改时给出内联保留/放弃操作。保存失败显示原错误并保留表单。

## 实施与验证

1. `PreviewSession.cs`：建立内存状态与固定时钟，核心 SavePlan/Preview 计算，允许模拟保存失败。
2. `PageUi.cs`、`PageWindow.cs`：共享页面、行、字段、操作区、主页状态与空态。
3. `PlanForm.cs`、`TimeFields.cs`：两种表单、时刻草稿、条件字段、校验和保存返回列表。
4. `PageVerification.cs`：检查真实新增/编辑/取消/失败、字段错误、次数与日期、保存联动、长文与紧凑窗口，输出截图与结果。
5. 独立发布、外部 UIA 验证、原稿与基准页对照、评审说明和启动入口。

当前默认方案为隔离页面样板，后续评审后再接入正式数据。直接替换旧程序会把页面评审与迁移混在一起，因此本阶段不进行；只出静态图则无法验证联动，故交付可操作原生页面。
