## 自动规则与存储验证：28/28 通过

证据：`artifacts/rules-test-results.json`。这些测试以明确的时间输入验证业务规则，不修改系统时钟。

| 主题 | 已验证结果 |
|---|---|
| 完成后间隔 | 09:37 确认，30 分钟间隔的下次为 10:07 |
| 延期 | 保持同一事项身份，不写入完成，延期期间不重复显示 |
| 固定药物时刻 | 本次晚确认不平移后续时刻，同一时刻扫描不重复生成 |
| 幂等 | 已完成事项重复确认不再次改变下次时间 |
| 会议 | 普通弹窗受抑制，到期恢复并缓冲；药物原计划不改变 |
| 暂停时的会议 | 即使全局提醒暂停，会议模式仍会到期结束 |
| 重启恢复 | 已完成事项不重复；错过的药物事项转待核实 |
| 药物特殊状态 | 不确定不等于已服用；不同药物分别记录 |
| 计划编辑 | 普通旧待办取消并留历史；药物旧待办保留待核实 |
| 参数约束 | 拒绝药物等间隔、药物办公时段继承及重复固定时刻 |
| 日期与时间 | 周末顺延、午夜、中国时区、固定事项时钟回拨去重 |
| 普通事项积压 | 每个计划不堆积多个普通补打卡，时段外不重复弹窗 |
| 长期未运行 | 超过 30 天明确提示较早历史需要自行核对 |
| 写入故障 | 注入保存异常后，不提交新的内存完成结果和下次时间 |
| 实际 SQLite | 中文与引号保存、事务提交、数据库重开、完整性检查通过 |

写入失败测试使用故障注入，不能代表所有断电与磁盘损坏场景已验证。

## WPF 界面与真实计时验证：15/15 通过

证据：`artifacts/gui-smoke/gui-test-results.json`。最终一轮直接运行自包含的 `Pausewell.exe`，开始于 15:16:40，结束于 15:17:26。

- 首次运行不自动开启实际提醒。
- 通过界面创建计划后，SQLite 中可读到结果。
- 活动未计时不能直接确认；实际 5 秒计时结束后仍需确认。
- 活动和服药预览不写入真实完成记录。
- 全屏窗口为置顶、无边框；本机实际物理窗口范围为 2520 × 1680。
- 全屏普通关闭被限制；两秒长按计时路径可以退出。
- 会议动作设置明确到期时间；真实调度器能自动结束会议并进入缓冲。
- 普通事项按真实时钟到期后，由后台调度展示窗口，经真实按钮事件确认并保存。
- SQLite 完整性检查通过，主窗口隐藏后可恢复且数据保留。

本轮只有一块显示器。覆盖数量计算通过，并不代表真正的多显示器环境已验证。长按测试调用与按钮共用的计时入口，没有代替真实鼠标与键盘长按的人机体验测试。

### 实际时间线

本次普通测试事项原计划 15:17:00 到期。先前的会议自动结束，按设计保留缓冲至 15:17:24.723。窗口被观察到的时间为 15:17:25.260，距可呈现时刻约 0.54 秒。

原计划到窗口出现之间的约 25 秒包含会议收尾缓冲，不应计作单纯调度误差。此为单次样本，不能据此宣称所有负载和系统场景均满足五秒目标。

- .NET SDK 10.0.402；本地工具链位于 `.tools/dotnet`，未修改全局 PATH。
- 运行时为 .NET 10.0.13；WPF、自包含 Windows x64 程序。
- Windows 自带 `winsqlite3.dll`，没有第三方 NuGet 应用依赖。
- 构建成功，无编译警告与错误。构建和验证 PowerShell 脚本语法检查通过。
- 自包含 EXE 为 173,127,280 字节，约 165.1 MiB；包体尚未优化。

正常应用启动后的一个七秒观察中，工作集约 247.8 MiB、CPU 时间增加约 968.8 ms，包含启动预热影响。稍后又观察到工作集约 305.2 MiB、七秒 CPU 增量 0 ms。两者只是当前机器上的短时观察，不是性能基准。不能据此宣称内存低或资源目标已达标。

## 阶段判断

最小流程已经可以运行和检查，当前结果支持进入本人对普通事项的体验与反馈阶段。它尚不足以支持正式发布、健康效果承诺或作为唯一服药提醒手段。

建议先体验创建、延期、完成、会议及全屏，记录哪些提醒被忽略、哪些打断不合适，再确定默认间隔、提醒强度和原型布局。接下来优先完善时间可靠性和真实系统场景验证，然后才扩大功能。
