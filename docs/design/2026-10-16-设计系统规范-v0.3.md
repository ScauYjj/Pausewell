# 间歇设计系统 v0.3.1

日期：2026-10-16。状态：用户已确认首轮原生组件打样效果，进入材质与光影样板阶段；材质效果和正式页面仍待评审。当前正式程序仍为 v0.2，数值可在后续打样中修正。文档保留原文件名作为固定入口。

本轮修订依据为用户提供的四张控件走查图。完整补充见 [控件配套设计与验收 v0.3.1](2026-10-16-控件配套设计与验收-v0.3.1.md)：新增下拉展开面、日历内部、复选与展开器、滚动条、键盘焦点及状态组合；同时明确既有规则尚未落地的问题。不能仅凭“统一高 40、圆角 10”判定一个组件完成。

## 1. 设计依据与范围

视觉依据继续使用已经选择的 `design/ui/轻透主题/01-暖香槟-默认.png`。保留商务、精致、简约、暖色透光、石墨主按钮与香槟开关，不重新发散风格。灰紫、陶土橙、雾玫瑰、雾蓝作为换肤，绿色不加入。

此前只定义了少量颜色和控件样式，尚未形成材质、排版、组件、页面及验收共同遵循的系统。v0.2 不能作为视觉验收通过的基线。本规范将这些约束补齐，适用于所有导航页、表单、提醒及辅助窗口。

**已经确认的方向：** 页面流程、默认风格和五主题。**本轮提出的规则：** 以下尺寸、材质参数、组件状态及页面模板。尺寸全部用 WPF DIP，100% 缩放时 1 DIP 对应 1 物理像素；不能把 150% 截图的像素直接写成控件尺寸。

机器可读值：`design/system/v0.3.1/tokens.json`，旧 `v0.3` 保留为历史基线。所有新样板先引用最新文件对应的语义，不在各页随意写不同数值；经评审调整时同时更新文档、tokens 和组件资源。输入高 40 等尺寸为正常字号的基准最小值，文字放大后应增高而非裁切。

## 2. 关于 Liquid Glass 的实现边界

Apple 的 Liquid Glass 包含动态光学行为、环境适应与运动响应，主要构成悬浮的导航和控制层。设计上需要保留清楚的内容层，不能只把整个页面调透明。[Apple：Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)

当前 WPF 的半透明纯色和一小块拉伸纹理没有这些特征。提高透明度、给所有控件加模糊也不足以解决。Windows 的 Acrylic 可建立半透明层次，Mica 是另一类背景材质；它们不能直接视为 Apple 光学效果的等价替代。[Microsoft：Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)、[Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)

本产品 v0.3 的交付目标是：在 Windows 上保住所选效果图的通透、边缘高光和空间关系，形成可读、稳定的原生界面。真实折射不是本轮已实现或已承诺的能力。先做可运行的局部材质样板，再决定是否需要更复杂的渲染方案，不因一个材质问题直接重写整个应用。

## 3. 材质与空间层级

| 层 | 用途 | 视觉职责 | 初始参数 |
|---|---|---|---|
| L0 环境底 | 应用自己拥有的全窗口背景 | 提供低对比暖色环境，让上层透光有可见对象；覆盖整个窗口，不能只放顶部横条 | 暖香槟基底 #F3EEE5，环境色 #EEE7D9；使用专用完整背景资产，不截取并拉伸一小块图稿 |
| L1 内容层 | 正文、列表、表单阅读区 | 稳定阅读，不把每行都做成玻璃 | 白色叠层 94% 为起始值，E1，圆角 16；卡片允许近实色 |
| L2 控制浮层 | 顶部导航、菜单、悬浮操作 | 让人看出浮在内容之上；有透射、顶部高光、底部接触阴影 | 白色叠层 56%，背景模糊初值 24 DIP，高光 80%，边缘暗部 8%，E2 |
| L3 任务浮层 | 提醒、会议和确认弹窗 | 建立比导航更清晰的抬升和聚焦，同时保证任务文案可读 | 白色叠层 78%，背景模糊初值 28 DIP，高光 86%，E3，圆角 24 |
| L3 内部阅读面 | 药名、日期、说明和错误 | 文本与背景稳定分离 | #FCFBF8、98%，不再叠加额外玻璃 |
| 遮罩 | 模态任务背后 | 降低竞争，不染成厚重棕灰色 | #181614、18% 初值；全屏遮罩另需实际试用 |

这些是材质打样的起始值，不能按填入数字即验收通过。需要同时检查明暗背景、长文本、失焦、低性能和减少透明度状态。整体内容层是否达到原稿的通透关系，是验收依据。

原生样板调校记录：v0.3.2 将导航/任务白色叠层试调为 48% / 62%，避免初值与明亮背景合成后接近实色。独立参数见 `design/system/v0.3.2/material-tuning.json`，不修改已确认的 v0.3.1 控件；材质新值尚待用户评审。

光照统一从左上方进入。外缘以细高光和极轻暗边表达厚度，禁止粗白边和四周均匀发光。邻近卡片不使用深阴影制造相互竞争。对嵌套控件保持同心关系，内部圆角不大于容器圆角。

| 阴影等级 | 层次 | 主阴影 x/y/blur/opacity | 接触阴影 |
|---|---|---|---|
| E1 | 内容卡片 | 0 / 2 / 8 / 4% | 无 |
| E2 | 导航、菜单 | 0 / 6 / 20 / 10% | 0 / 1 / 3 / 5% |
| E3 | 任务弹窗 | 0 / 16 / 48 / 16% | 0 / 2 / 8 / 8% |

阴影颜色统一 #31291E。参数是项目自定初值，不是 Apple 官方参数。WPF 多阴影可用容器分层表达，不把 BlurEffect 施加到带文字的整个控件树。

## 4. 配色与主题

主题只替换主动作、开关、选中态、浅强调底和环境色；文字、错误、边界和状态语义不随主题改变。主题不能变成给全页蒙一层主色。

|---|---|---|---|---|
| 暖香槟，默认 | #343434 | #9B8D70 | #F3EEE5 | #EEE7D9 |
| 灰紫 | #795280 | #795280 | #F1EAF3 | #E9E2EC |
| 陶土橙 | #AA5B32 | #AA5B32 | #F7ECE4 | #F0E4D8 |
| 雾玫瑰 | #A0526B | #A0526B | #F7EAF0 | #EEE1E5 |
| 雾蓝 | #4C6D91 | #4C6D91 | #EBF2F8 | #E2E8EF |

正文 #292824；次级文字 #65615B；辅助文字 #746F67。装饰性卡片边界 #D9D5CD，列表分隔 #E8E4DD；依赖边界识别的输入控件使用 #8D877D，不把低对比装饰线当成功能边界。错误 #A14B43 配 #F9EDEA；提醒注意 #805C20 配 #F8F1E2。完成状态使用文字和标准勾选图标，不强制引入绿色。状态不能只靠颜色表达。

普通文本按 4.5:1、大字号和有意义的控件边界按 3:1 作为验收目标。数值来自通用可访问性要求，实际玻璃表面仍需按最终合成背景测量，不能只测白底上的色值。[W3C：文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 5. 字体、数字和文本

中文与常规 UI 使用 Microsoft YaHei UI，缺失时回退 Microsoft YaHei；时间数字使用 Segoe UI，使用等宽数字特性便于对齐。不得将字体形状和生成效果图的未知字体宣称为完全一致。

| 角色 | 字号 / 行高 | 字重 | 使用位置 |
|---|---|---|---|
| 页面标题 | 28 / 40 | Semibold | 提醒状态、服药、记录、设置 |
| 弹窗标题 | 24 / 34 | Semibold | 新增、会议、记录确认 |
| 区块标题 | 18 / 28 | Semibold | 我的提醒、通用设置分组 |
| 事项名称 | 16 / 24 | Semibold | 列表与卡片名称 |
| 正文 | 14 / 22 | Regular | 说明、规则和按钮 |
| 字段标签 | 14 / 20 | Semibold | 字段上方标签 |
| 辅助文字 | 12 / 18 | Regular | 非关键补充、底部说明 |
| 主要时间 | 44 / 56 | Semibold | 当天 HH:mm |
| 长时间 | 28 / 40 | Semibold | 带日期的 MM-dd HH:mm |

执行要求：时间与单位之间空 4 至 8 DIP；同一列右/左对齐统一。正文不小于 14；重要确认、药名和时间不使用 12 号。长事项名最多两行，超过后省略并能查看完整内容；不能挤掉状态和编辑按钮。时间不能简单缩成不可读字号，跨日时改用长时间样式。

## 6. 间距、尺寸与布局

基础间距为 4 DIP，常用序列 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48。禁止每页重复出现 10、14、18、22、26、28 等互不关联的容器间距；字体字号不受此条限制。确有光学校正时，只能在共享组件内部记录例外。

| 对象 | 规则 |
|---|---|
| 主窗口 | 默认 1200 × 860，最小 900 × 650；视觉对照额外固定 1004 × 866 |
| 全窗口外沿 / 内容内边距 | 16 / 24 |
| 导航区域 / 胶囊高度 | 88 / 56，导航在玻璃背景中居中 |
| 区块间距 | 24；标题与下一层 12；页面标题下 20 |
| 下次提醒卡 | 基准高度 160，内边距 24，图标区 80 |
| 列表表头 / 常规行 | 40 / 80；长文案允许行高增长，不裁切 |
| 字段标签到输入框 | 8 |
| 输入框到辅助 / 错误 | 6 |
| 字段组之间 | 24 |
| 弹窗内容内边距 / 底部操作区 | 32 / 80 |
| 普通表单 / 药物表单宽 | 640 / 720 |
| 会议 / 记录 / 常规提醒宽 | 480 / 640 / 480 |
| 弹窗高度 | 内容驱动，最大工作区高度减 48；主体滚动，标题与操作区固定 |

默认首页有三条普通事项时，应能在基准窗口内看到三条及其操作。移除首页底部重复占位的“服药计划数量”大条，服药入口由顶部导航承担，必要时导航显示数量标记。该内容不是已确认的必要主任务，不应挤出提醒列表。

最小窗口允许主体滚动，但导航、保存/取消、紧急退出不得被遮住。页面窄于 1040 时，长筛选条分两行、主题卡从五列变三列，不把每个卡片挤成小缩略图。最大窗口正文设合理最大宽度，避免表单字段无限拉长。

## 7. 组件契约

所有组件必须有同一套资源与状态定义。页面只能组合共享组件，不再每页手写一套边框、按钮和表单。

### 7.1 按钮与导航

- 常规按钮高 40，小按钮高 32，提醒主动作高 44；水平内边距 16，按钮间距 8，圆角 10。
- 一个任务区只有一个主动作，使用主题 Primary；次动作使用稳定阅读面和细边界；取消不与确认争夺颜色。危险动作使用语义错误色。
- Default、Hover、Pressed、Focus、Disabled、Busy 六态分别定义。悬停改变表面或明度，不整体降低透明度让文字也变淡。按下阴影缩小，位移最多 1 DIP。
- 焦点使用外侧 2 DIP 环，间隔 2；不能把边框从 1 改 2 导致内容跳动。Busy 保留按钮宽度并阻止重复提交。
- 顶部导航高 56，四入口使用一致图标 20 和正文 14；当前项使用独立抬升面，不能只有模糊的底色变化。键盘焦点与选中态同时存在时仍可分辨。

### 7.2 开关、复选和选项

- 开关轨道 48 × 28，白色滑块 22；点击区至少 48 × 36。启用用主题 Toggle，关闭用 #8B8985，文字显示“开启/关闭”。默认开关保持香槟，不改成黑色。
- 开关承担立即生效的启停。设置页尚未保存的开关属于草稿，必须有固定保存区和离开处理；不能让人以为已经全局生效。
- 复选框用于组合设置，单选/分段选项用于互斥选择。不能统一用小方框替代所有语义。
- 药物每天 1/2/3/4 次的数量选择必须有明确选中态，新增时刻后同步当前数量；这只是字段数量，不自动替用户算服药间隔。

### 7.3 输入、选择、日期时间

本节为基础原则，完整组件结构、展开态、键盘行为与验收以 v0.3.1 控件补充规范为准。DatePicker 的内部文本框、Calendar、月份/年份按钮，以及 ComboBox 的 Popup/选项/滚动都在设计范围内。

- 输入框、下拉框、日期选择和时间字段统一高 40、圆角 10、内边距 12、正文 14；不保留灰色系统默认下拉框与自绘圆角输入框混用的状态。
- 标签始终在上方，提示文字不承担标签职责。必填、可选、单位分别清楚表达。日期与时间字段形成同一行时基线对齐。
- Empty、Hover、Focus、Filled、Error、Disabled、ReadOnly 七态定义。错误使用边界、图标和文字组合，出现在对应字段下方；提交失败不抹掉输入。
- 初次打开不报错，提交后或已经操作过的字段失焦后校验。禁用的条件字段可折叠，不长期占据大块空白。
- 时间用 HH:mm，限制输入并解释具体原因；实际服用日期/时间和记录确认时间始终区分。未知时间为明确选择，不能伪造当前时间。

### 7.4 列表、卡片与提示

记录页基准采用日期分组外壳与内部行分隔，避免相邻行圆角黏连；若用独立卡片，外间距应写在卡片外壳。滚动条、滚动容器和输入方式焦点的完整要求见 v0.3.1 补充，不可继续借用旧系统模板作为设计完成状态。

- 普通列表字段顺序：事项图标、名称与规则、下次时间、状态、编辑。列表不是一排深阴影卡片；分隔线足够，不每行再加外框。
- 提醒列表和药物列表共享行高、图标、状态和操作位置，但药物行展示明确时刻，不能显示“完成后再等若干分钟”。
- 内容卡片用 E1，浮动菜单用 E2，任务弹窗用 E3；禁止统一调用一个没有角色的 `Panel()` 覆盖所有层级。
- 提示条区分信息、注意、错误。常驻说明尽量用正文，不为每一行说明都增加色块。
- 状态标签固定高度 24、字号 12，文字简短并有图标；待核实不能包装成“已完成”。

### 7.5 弹窗、提醒和记录

- 标题、主体、底部操作为固定骨架；主体超高时内部滚动，操作区固定。取消位于主动作左侧，返回保持同一习惯。
- 一次提醒的主动作直说结果：确认已喝水、开始活动、当前无需、记录已服用。普通提醒的延期和会议入口位置保持一致。
- 活动开始、计时中、计时结束待确认是三种不同状态。换肤不重置计时。
- 服药从提醒进入实际信息确认，后续计划不平移；未知、未服用、已服用均有可区分的样式。药名与实际时间用稳定阅读面承载。
- 记录详情按原计划、实际、确认三组展示；更正显示前后值与原因。关闭或延期从不写成完成。
- 全屏紧急退出始终可见，鼠标与键盘长按都有明确进度，普通键关闭不得制造完成记录。

## 8. 页面级设计要求

下表覆盖整个现有产品，不代表本轮已经把所有页面重画完成。每个页面进入开发前，需要对应高保真图及关键状态稿。

| 页面/窗口 | 布局与主要组件 | 必须提供的状态 | 本轮发现的优先修正 |
|---|---|---|---|
| 提醒首页 | 共用壳、状态标题、会议/暂停、下次卡、普通列表；主要任务优先 | 首次、提醒中、会议、暂停、待处理、全部关闭、错误 | 恢复全窗口材质关系；三条常用事项完整展示；去除底部重复数量大条 |
| 普通新增/编辑 | 共用表单骨架；名称、事项、间隔、方式；更多设置折叠 | 初始、填写、非法值、更多展开、保存中、保存失败；会议/暂停语义 | 统一输入和下拉；减少不必要的滚动；固定操作区 |
| 服药列表 | 共用标题、药物行、时刻、状态与编辑；待核实入口单独提示 | 无药物、已启用、停用、待核实、多个到期、长药名 | 列表与普通首页统一密度；避免一条记录后整屏失去组织 |
| 药物新增/编辑 | 明确时刻组、次数分段、日期组、已有说明、提醒方式 | 空白、1/2/3/4/更多、跨日说明、结束日期、错误、停用 | 数量选择态、日期基线、字段间距和固定保存区 |
| 执行记录 | 固定标题、分组筛选、日期范围、结果列表 | 初始空、筛选无结果、已有记录、长文案、历史缺口、超200条 | 下拉与日期统一；空状态放在适当阅读区域，不能只有细色条 |
| 记录详情/更正 | 摘要、三类时间、结果、更正区、修改历史 | 待处理、已记录、未知实际时间、更正、错误、历史展开 | 摘要层次与时间对齐；必须查看已完成记录后才能验收，此次空演示未覆盖 |
| 通用设置 | 主标题、分组设置行、说明；固定保存区；数据与退出放末组 | 草稿、无变化、已修改、保存成功、失败、受限项 | 用统一设置行取代散落的小复选框，解释与开关对齐 |
| 外观设置 | 同一设置骨架、主题卡、选中态、组件预览、固定保存 | 初始、预览、已选、取消、保存失败、减少透明度 | 缩略图不能代替真实组件预览；宽窄不同列数，保持文字可读 |
| 会议/暂停 | 共用任务浮层；时长、恢复时刻、药物范围与明确主动作 | 初始、时长错误、完全静音、含药物暂停、延长、提前结束 | 统一圆角、材质、输入；统一底部按钮靠右，消除与主窗口的视觉断层 |
| 会后待办 | 分组普通/服药、原计划、逐项动作、延期返回 | 无待办、多项、逐项完成、待核实、返回延期、保存失败 | 复用共享行与状态；需要造隔离待办后补拍，不用此次普通首页图冒充 |
| 喝水/活动/如厕 | 一致任务浮层、事项图标、标题、结果主动作、延期 | 到期、预览、活动三阶段、当前无需、延期、紧急退出 | 减轻棕灰底和大白片割裂；次动作从孤立左下改成一致操作组 |
| 服药提醒/确认 | 任务浮层加稳定信息区；药名、原计划、实际与结果 | 到期、已服用确认、未知、未服用、待核实、多药、失败 | 复用字段和确认骨架；不用普通预览截图替代服药确认验收 |
| 托盘菜单/系统轻提示 | 标准 Windows 菜单、简短动作、隐私文案 | 运行、会议、暂停、错误、退出 | 尊重系统可访问性；无需强行自绘玻璃菜单 |

## 9. 动效和降级

Hover 120ms，Pressed 80ms，开关 160ms，弹窗 180ms，页面 160ms。无持续流光、呼吸、自动漂浮和背景循环；办公提醒工具不能为了材质持续占用 GPU。

减少动效时使用直接状态切换，减少透明度/高对比度/低性能时使用实色回退。系统设置优先于外观皮肤。失焦后层次略收敛，但关键确认、延期、退出仍清晰。

性能阈值先作为专项验证目标：空闲不持续重绘；背景只在主题、尺寸或内容变化时更新；提醒出现与时钟调度不得被视觉渲染阻塞。具体 CPU/GPU/内存门槛需在记录设备配置后制定，不能凭空宣称已达标。

## 10. WPF 实施约束

1. 建立 `DesignTokens`、`MaterialSurface`、`Button`、`FormField`、`SettingsRow`、`HabitRow`、`DialogShell` 等公共资源。页面只引用语义角色，避免复制数字。
2. 全窗口 L0 独立于文本；模糊只处理应用自己拥有的背景层。内容和按钮在模糊之外清晰绘制，避免“磨砂文字”。不得以连续截屏桌面或其他应用来伪造玻璃。
3. 不把系统 Acrylic 参数直接填入 WPF BlurEffect 后宣称已有背景透射。先通过同场景原生样板证明效果；支持系统合成的方案另行做兼容、功耗与降级验证。
4. 五种主题共用布局、材质级别和状态。设置中的局部预览、全局保存、取消与持久化语义沿用已确认流程。
5. 本次视觉改造保持核心调度、存储和药物规则；不得为了视觉样板迁移或改写正常提醒数据。

## 11. 设计交付及验收

设计交付分三层：规范和 tokens；可运行的原生组件/材质样板；完整页面和状态稿。三者齐备后再逐页接入应用。

先打样导航、下次提醒卡、任务弹窗三块，因为它们能直接验证透光、边缘与空间层次。用同一套组件再完成首页、普通表单、服药表单三个页面，确认可复用后扩展到其他页面。暂不以换一个框架作为解决视觉问题的前提。

每个页面需通过以下独立门槛：

- **流程：** 主动作、取消、失败、空状态可理解且实际有效。
- **视觉：** 选定效果图/页面稿与同尺寸、同主题、同状态截图并排；材质、主要区域比例、字体层级和间距偏差逐条处理。
- **组件：** 同名控件没有自行改变高度、边距、圆角、颜色和焦点处理。
- **阅读：** 长药名、跨日时间和两行规则不覆盖操作；可访问性对比按实际合成背景检查。
- **设备：** 100/125/150/200% DPI，独立测试 100/125/150/200% 文字缩放；最小窗口、工作区限制、减少透明度与动效。
- **性能：** 空闲不持续绘制；主题变化和提醒调度互不重置；失败降级保持操作。

有主要材质或空间层次差异时，视觉门槛不能写 passed；按钮能点、规则测试通过和截图已生成都不能替代视觉验收。未确认的页面细节标为待评审，不写成已获确认。
